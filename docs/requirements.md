# AutoRustDesk 需求说明（已确认）

## 1. 目标

在电脑 A 上提供一个带图形界面的"一键远控"工具：用网线把 A 和电脑 B（Ubuntu 20.04）直连后，程序自动完成

> 组网 → 找到 B 的 IP → （按需）离线安装 RustDesk → 配置 RustDesk 与 B 的系统 → 在 A 上打开 B 的桌面

全程不需要互联网，也不需要在 B 上手工操作。

## 2. 使用场景与约束

| 项目 | 说明 |
|---|---|
| 电脑 A（控制端） | 有屏幕的笔记本或台式机，运行本程序和 RustDesk 客户端。**需支持 Ubuntu、Windows、macOS，优先 Ubuntu** |
| 电脑 B（被控端） | Ubuntu 20.04 **桌面版**、x86_64、X11；已开启 SSH，有可用 sudo 的账号；**没接显示器，开机不自动登录**；通常不能上外网。后续扩展：22.04 / 24.04 同样支持，26.04 只能部分支持（只有 Wayland） |
| B 的网口 | 不确定是 DHCP 还是固定 IP；B 可能还连着别的网络（但没有外网） |
| 链路 | 一根网线点对点直连；链路上没有路由器、DHCP 服务、互联网 |
| 设备数量 | 多台同型号设备，**一次只连一台** |
| RustDesk | 使用 GitHub Release 页面的官方最新 deb（已验证可在 20.04 上安装） |
| 连接方式 | 本期只做网线直连（RustDesk "IP 直连"），不做跨互联网远程 |

## 3. 已确认事项

| 问题 | 答复 |
|---|---|
| A 的操作系统 | 三个系统都要支持，先做 Ubuntu |
| B 的系统 | Ubuntu 20.04 桌面版，x86_64，X11 |
| B 的 SSH / sudo | 有 |
| B 能否上外网 | 通常不能 → 必须离线部署 |
| B 的显示器 / 自动登录 | 没接显示器；开机不自动登录 |
| B 的网口配置 | 不清楚；可能连着其他网络 |
| 部署形式 | 离线部署包（官方 deb + 依赖 + 一键安装配置） |
| 连接范围 | 暂时只做网线直连 |
| 设备规模 | 多台同型号，一次连一台 |
| 程序形式 | 图形界面；开发语言不限 |

## 4. 功能需求

### F1 本机网络准备
- 列出 A 的有线网卡，自动选中插了网线的那块；显示链路状态。
- 在该网卡上配置直连专用网段（默认 `192.168.77.1/24`，可改），**不设网关、不改 DNS**，不影响 A 的 Wi-Fi 上网。
- 在该网卡上临时运行 DHCP 服务：只分配地址，**不下发网关和 DNS**，避免影响 B 的其它网络。
- 发现该网口上已有别的 DHCP 服务，或连着多台设备（说明插的不是直连线）时，不启动 DHCP 服务，并提示用户。
- 程序退出或点"恢复本机网络"时，把网卡恢复原状。

### F2 发现电脑 B
- B 用 DHCP：从 DHCP 分配记录直接拿到 IP。
- B 用固定 IP：通过 IPv6 链路本地地址（`fe80::`）和被动监听 ARP/IP 报文找到 B。
- 显示 B 的 MAC、IP、主机名；链路上有多个候选时由用户选择。
- 长时间找不到时给出排查提示（B 是否开机、拔插网线等）。

### F3 登录 B
- SSH 登录（账号密码或私钥），检查 sudo 权限。
- 首次连接记录 B 的主机密钥（按 MAC 区分设备），之后发现密钥变化时提醒。
- 同型号设备通常共用账号，可记住上次使用的账号（密码可选保存）。

### F4 检查 B 的环境
- 系统版本、架构、RustDesk 是否安装及版本、服务状态、显示管理器、GDM 是否禁用 Wayland、是否接了显示器、会话状态、防火墙、磁盘空间等。
- 不满足前提（非 x86_64、非 20.04、空间不足等）时明确提示。

### F5 离线安装 RustDesk
- 离线部署包包含：官方 RustDesk deb、Ubuntu 20.04 amd64 下的完整依赖、虚拟显示驱动 `xserver-xorg-video-dummy`。
- B 未安装或版本低于部署包时，上传部署包并用本地软件源离线安装；不会删除 B 上已有软件包。
- 提供"制作离线包"功能：在有网的电脑上，用下载好的 RustDesk deb 自动下载依赖并生成部署包。

### F6 配置 RustDesk 与 B 的系统
- RustDesk：设置固定密码、开启 IP 直连（端口 21118）、只使用固定密码、免人工确认、IP 白名单（只允许直连网段）。
- 登录界面：GDM 禁用 Wayland（`WaylandEnable=false`），使 RustDesk 能控制登录界面。
- 无显示器：安装并启用虚拟显示器（分辨率可设，默认 1920x1080）；开机时自动判断：接了显示器用真实显示器，没接就用虚拟显示器。
- 防止 B 在登录界面自动休眠导致失联（可关闭）。
- 若 ufw 已启用，放行直连网段访问 21118 端口。
- 需要重启显示服务时：B 上无人登录则自动重启；有人登录时先征求用户同意。

### F7 验证与连接
- B 为固定 IP 时，给 B 的直连网口临时加一个直连网段地址（不修改 B 的网络配置，重启后消失）。
- 从 A 检查 B 的 21118 端口可达。
- 在 A 上自动打开 RustDesk 客户端，以"IP + 密码"连接 B。B 未登录时，看到的是 B 的登录界面，直接输入 B 的系统密码登录。

### F8 设备记录
- 按 MAC 记录每台 B：主机名、分配的 IP、SSH 账号、主机密钥、RustDesk 密码与版本、上次配置时间。
- 已配置过的设备可"快速连接"：跳过安装和配置，直接连。

### F9 日志
- 每一步显示进度和结果，出错时给出原因和建议；日志可导出。

## 5. 非功能需求
- **全程离线**：A、B 都不需要联网（只有"制作离线包"需要联网）。
- **可重复执行**：重复运行不破坏已有配置；已满足的步骤自动跳过。
- **不破坏原有网络**：不改 A 的默认路由和 DNS；B 上只做临时地址，不改其网络配置。
- **权限最小化**：界面以普通用户运行，只有网络操作通过系统授权（pkexec）以 root 运行。
- **凭据安全**：密码不出现在命令行参数中；本地记录文件仅当前用户可读。

## 6. 本期不做
- 跨互联网远程、自建 RustDesk ID/中继服务器。
- 自己编译或改名定制 RustDesk。
- B 没有 SSH 时的 U 盘引导（后续可加）。
- 一次同时连接多台 B。

## 7. 风险与应对

| 风险 | 应对 |
|---|---|
| B 无显示器时 X 起不来或分辨率异常 | 虚拟显示驱动 + 开机自动切换；实在不行用 HDMI 显卡欺骗器 |
| GDM 登录界面走 Wayland，RustDesk 无法控制 | 设置 `WaylandEnable=false` 并清除注释行（RustDesk 会按注释行判断） |
| 新版 RustDesk 已移除 `allow-linux-headless` 无头模式 | 不依赖该选项，自行配置虚拟显示器 |
| B 用 DHCP 但链路上没有 DHCP，NetworkManager 反复失败 | A 运行 DHCP 服务；超时提示拔插网线 |
| B 网口为固定 IP 且禁用了 IPv6 | 被动监听 B 的 ARP/IP 报文，A 临时加同网段地址 |
| 离线安装缺依赖 | 部署包包含完整依赖闭包，本地源安装，禁止删除已有包 |
| 插错网线，给公司网络乱发地址 | 检测到其它 DHCP 服务或多台设备时不启动 DHCP |

## 8. 分期
1. **第一期**：A = Ubuntu，完成 F1–F9。
2. **第二期**：A = Windows（网卡配置用 netsh，程序以管理员运行）。
3. **第三期**：A = macOS（networksetup + 授权助手）。
4. 之后：B 无 SSH 的 U 盘引导、自建服务器远程等。
